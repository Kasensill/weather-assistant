# 大气科学科普助手 (Weather Assistant)

> 项目最后更新: 2026-08-20

一个基于 RAG(检索增强生成)技术的气象科普问答助手,面向大众解答天气现象和大气科学基础原理。

## 项目背景

作者(前端 Vue+TS 背景,兼具 Python 基础)向 AI 全栈工程师方向转型的第一个实战项目,选择"大气科学科普"作为垂直领域切入点。目标是通过完整实现一个 RAG 系统,掌握从知识库构建到检索问答的全链路能力。

## 技术栈与选型理由

| 环节 | 选型 | 为什么选它 |
|---|---|---|
| 开发语言 | Python 3.11.9 | 3.10 太旧,3.12+ 部分库(如 ChromaDB)兼容性不完善,3.11.9 是最后一个有图形化安装包的 3.11 版本 |
| 环境隔离 | venv | 比 Anaconda 更轻量,更符合行业标准做法,项目级隔离足够用 |
| 对话模型 | DeepSeek (deepseek-v4-flash) | 价格低、注册简单、国内直连稳定;flash 版本对 RAG 问答场景够用,无需上 pro |
| 向量化(Embedding) | 阿里云百炼 (qwen3.7-text-embedding) | DeepSeek 官方无 Embedding 接口(已查证);阿里云新用户有 100 万 Tokens 免费额度(有效期至 2026/11/19),且是目前该系列最新最强的向量模型 |
| 向量数据库 | ChromaDB | 轻量、本地部署、几行代码跑通,适合当前 90 条记录的小规模场景;Milvus 是同类but面向千万级以上数据的重量级方案,当前规模不需要 |
| 文档切分 | LangChain MarkdownHeaderTextSplitter | 按 `#`/`##` 标题切分,天然保留语义完整性,比按字符数硬切更适合结构化的 md 知识库 |

## 核心概念备忘(供快速回顾)

**RAG = Retrieval(检索) + Augmented Generation(增强生成)**
- 与普通大模型对话的本质区别: 普通对话只有 G(完全依赖模型训练时的内在知识,不可控、不可追溯);RAG 多了 R,先从自有知识库检索相关内容,再让模型基于这些内容生成回答,因此可追溯、可控、可随时更新知识而不需要重新训练模型
- 验证"回答是否真的基于知识库"的方法: 修改某个知识条目内容 → 重新向量化 → 同样的问题应该得到相应变化的回答

**Embedding 与对话模型的区别**
- Embedding: 把文本转换成固定长度的向量,用于语义检索,计算量相对小,价格低(阿里云 0.5元/百万Token)
- 对话模型: 逐字生成回答,计算量大,价格更高
- 一次问答通常至少调用一次 Embedding(问题向量化)+ 一次对话模型(生成回答)

**ChromaDB vs Milvus**
- ChromaDB: 轻量本地方案,适合中小规模(当前90条记录场景)
- Milvus: 面向千万级以上向量的生产级方案,当前项目规模暂不需要

## 开源与部署相关备忘

- `.env` 文件已在 `.gitignore` 中排除,不会被上传
- 如需开源,应提供 `.env.example`(仅含变量名,不含真实密钥),使用者需自行申请并配置各服务的 API Key
- 若未来提供在线 Demo,需自行承担访问者的 API 调用成本,通常需要做限流设计(参考各类 AI 工具的"每日免费额度+会员"模式)
- 云端向量数据库(如 Zilliz Cloud、阿里云 DashVector)是未来可选的部署方向,相比本地 ChromaDB 增加网络查询延迟和查询计费,但省去自建服务器运维向量数据库的负担
