# 上下文工程（Context Engineering）

这是 Prompt 工程升级版。

最近招聘大量出现。

# 实际 Agent 系统：

        用户问题

        +
        历史聊天

        +
        知识库

        +
        工具结果

        +
        任务状态

        +
        用户信息

        ↓

        送给LLM

*** 这个整体叫：***

Context

# 举个例子：

## 用户：

为什么会形成台风？

## 真正给模型的不是：

为什么会形成台风？

## 而是：

### 系统：
你是气象专家

### 历史：
用户之前问过季风

### 知识库：
台风.md
海温.md
热带气旋.md

### 当前问题：
为什么形成台风？

### 工具：
无

### 请回答

## 这整个设计：

就是***上下文工程***
Context = 当前这一轮送给LLM的全部信息。

# 核心问题：

什么信息应该给模型？

给多少？

什么时候给？

# 这其中包括：

长上下文管理：现在模型上下文越来越长，会导致很多问题，所以要管理。
历史压缩：应对历史聊天过长，压缩，减少token。
Memory：记忆，分为短期记忆（当前会话）和长期记忆（跨会话，数据库保存）。
RAG召回：其实也是Context工程，不能把知识库全部的东西都给LLM，所以召回top_5的信息加入上下文，再给LLM。
Prompt模板：是一个固定结构，如：

        角色

        规则

        资料

        问题

        输出格式

状态管理：Agent非常重要的部分，普通聊天没有状态，但agent有，他处理问题分的几个任务都有状态，如

        目标：
        写报告

        完成：
        数据收集 √

        当前：
        分析数据

        下一步：
        生成图表

他们都是管理Context的方法。
