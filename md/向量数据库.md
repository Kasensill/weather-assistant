# 向量数据库

## 与普通数据库的区别

### SQL 数据库（以 MySQL 为例）

> 数据模型:结构化表格

            | id | name  | age | city      |
            |----|-------|-----|-----------|
            | 1  | 张三  | 28  | 北京      |
            | 2  | 李四  | 35  | 上海      |

·每一行是一条完整记录，每一列有固定类型（INT、VARCHAR 等）
·数据以行/页为单位存储在磁盘上（InnoDB 的 B+ 树结构）
·写入时保证 ACID 事务，数据强一致
·存储的是原始值本身     

> 底层结构：B+ 树索引

查询走索引 = 在 B+ 树上做精确/范围比较，时间复杂度 O(log n)

### 向量数据库（以 Milvus / Chroma 为例）

> 数据模型：向量 + 元数据

            | id | vector (768维浮点数)          | metadata              |
            |----|-------------------------------|-----------------------|
            | 1  | [0.12, -0.05, 0.88, ...]     | {"source": "doc_a"}   |
            | 2  | [0.33, 0.21, -0.17, ...]     | {"source": "doc_b"}   |

·核心存储的是高维向量（embedding），通常 128～4096 维浮点数
·向量本身没有"大小"语义——你不能说一个向量"大于"另一个向量
·向量旁边可以挂少量标量元数据（类似标签）

> 底层结构：近似最近邻（ANN）索引

向量数据库不用 B+ 树，而是用专为"找最相似邻居"设计的结构。
查询时从顶层入口点开始，贪心往目标方向跳，逐层下降，最终在 Layer 0 找到最近邻。
时间复杂度约 O(log n)，但不保证精确。


## 查询上的逻辑对比
MySQL：精确匹配 + 范围扫描，基于等值/大小比较，走 B+ 树索引，结果是确定的、精确的、可排序的。
向量数据库：给定查询向量，找距离最近的 k 个向量，效果是近似（ANN 牺牲精度换速度）。

# 常见的向量数据库

## 专用向量数据库

### Milvus（Zilliz 开源）
国产开源，大规模，云原生分布式向量数据库，为十亿～千亿级向量设计。

### Qdrant
用 Rust 编写的开源向量数据库，主打高性能 + 强元数据过滤。

### Weaviate
Go 编写的开源向量数据库，强调语义层 + 混合搜索（BM25 + 向量）。

### Pinecone☁️
全托管的 Serverless 向量数据库 SaaS，闭源，闭源、有供应商锁定，数据存第三方云，大规模成本较高。

### Chroma（ChromaDB）
Python 优先的轻量级开源向量数据库，，与 LangChain/LlamaIndex 深度集成，不支持分布式，数据量约百万级上限，无内置混合搜索，不适合直接上生产大规模集群。

## 向量检索库（非完整数据库）
### FAISS（Facebook AI Similarity Search）
Meta 开源的向量检索算法库（C++ 实现 + Python 绑定），不是数据库。

## 传统数据库的向量扩展 / 搜索平台
### 🐘 pgvector（PostgreSQL 扩展）
PG 的 C 扩展，给现有 Postgres 加向量列类型 + HNSW/IVFFlat 索引，单机为主，超大规模（千万级以上）需调优，向量性能不如专用库。

### Elasticsearch / OpenSearch
搜索引擎增加向量字段，支持 BM25 + 向量混合检索（RRF 融合），向量性能不及专用向量库，资源开销大。

### ⚡ Redis（Redis Stack）【内存数据库】
内存 KV 数据库增加向量索引（HNSW/FLAT），超低延迟（毫秒级），但内存成本高，数据量受内存限制

## 其他类型
### MongoDB Atlas Vector Search（简称 Atlas Vector Search）
是 MongoDB Atlas 托管云服务提供的向量检索能力——它不是独立数据库，而是让你在已有的 MongoDB 集合里直接存向量、建向量索引、用聚合管道做 ANN/ENN 相似性搜索。
就是在你的 MongoDB 文档里加一个向量字段 + 建 HNSW 索引 + 用 $vectorSearch 做 ANN 查询。最大优势是文档数据与向量同源存储、同库查询，省去同步双写；代价是锁定 MongoDB Atlas 云服务，且在超大规模纯向量场景下性能不如专用向量数据库。

# FAISS 和向量数据库区别
FAISS是一个搜索库，提供：

        向量
          ↓
        索引
          ↓
        最近邻搜索

但FAISS不负责：

        用户权限
        数据管理
        API
        持久化系统
        分布式

向量数据库就是在FAISS的基础能力上加入了一整套数据库能力。
