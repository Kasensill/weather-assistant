# 欧氏距离（L2）、余弦距离（cosine）、内积（IP, inner product），不是 Chroma 独有，而是向量检索里非常通用的三种度量/相似性方式。
## 欧氏距离（L2）：
### 两个点之间的直线距离，即两个向量在空间里实际离得多远。分量（对应坐标）相减，平方，各部分求和，整体再开根号
### 适用场景：图像特征、空间坐标、某些机器学习 embedding、模型训练时本身就按 L2 优化的向量

## 余弦距离（cosine）【同时可以表示成 similarity，也可以表示成 distance】：
### 它们是不是朝着同一个方向，两个向量夹角越小，余弦相似度越高。
### 文本语义检索最常见
### 余弦相似度 Cosine Similarity：cos(θ) 越大越相似，1 → 非常相似 | 0 → 无关 | -1 → 方向相反
### 余弦距离 Cosine Distance：1−cos(θ) 越小越相似， 0 → 非常相似 | 1 → 无关 | 2 → 相反，Similarity 和 Distance 的数值方向相反，为了用距离的形式表达同一种方向关系，进行一个单调变换，为了表达——越小→越接近 这个效果

## 内积（IP, inner product）【Similarity / Score】：
### 实际上内积就是A⋅B，A⋅B=a1​b1​+a2​b2​+a3​b3​，它实际上同时受到两个因素影响：两个向量的方向+两个向量的长度（向量就是由长度和方向决定）.
### 模型明确按它设计时使用

# 归一化：统一所有向量的长度，让相似性主要体现在方向上，三个相似度排序结果一致
# 一旦不归一化，三者一般不再产生相同的排序，因为这时候向量的长度也开始参与计算

# 当前归一化问题的核心：Qwen 把所有 embedding 向量统一到了单位球面上；在单位球面上，L2²、cosine distance、cosine similarity、inner product 之间都存在严格的单调变换，因此用它们做 Top-K 检索时，排名是一样的，只是返回的数值表达方式不同。

# 一个具体的 embedding 模型确实定义了一个统一的高维向量空间，但它是模型自己通过训练学出来的语义空间。但问题来了：模型凭什么知道“彩虹”和“水滴”应该靠近？答案是：训练。训练会不断调整模型参数，让它们最终在向量空间里形成某种结构。核心思想一样：语义相近的东西，在这个空间里倾向于形成相近的位置或方向。

# 这个空间一般来说是模型为了完成“理解语言”这个任务，自己构造出来的一套数学内部表示。我们只能通过：向量距离、向量方向和向量之间的关系去观察它形成的结构。

# 要注意，不同 embedding 模型之间不是同一个空间。模型训练目标使语义/上下文关系相近的文本产生更相近的表示。

## 首先把天气知识库 Markdown 按标题切成知识块，然后使用 Qwen Embedding 模型将每个知识块转换成向量并存入 Chroma。用户提问时，对问题使用同一个 embedding 模型生成 query vector，再通过 Chroma 做 Top-K 向量检索，根据距离找到最相关的知识块，最后把用户问题和检索到的知识作为上下文交给 LLM 生成回答。

# Chunk 的目的不是“把文本切碎”，而是让一个 Chunk 尽可能围绕一个相对完整的语义单元。

# Chroma 的 distance 默认是从小到大返回的，所以 Top-K 本质是：找距离最近的 K 个向量。
# Chroma 输出的是 L2 的平方，即Chroma 的 l2 空间返回的是 squared L2 distance，而不是带平方根的普通欧氏距离。排序根本不需要开平方，因此很多向量检索实现直接使用 squared L2。L2代表这个类型，不代表是否开平方。

# 内积相似度： A⋅B=∣∣A∣∣∣∣B∣∣cosθ， 同时考虑长度（两个向量的模）和方向，长度变了的时候内积是要变的。

# 欧氏距离L2：距离不是线性的“相关程度”，不能说0.2 比 0.8 “相关 4 倍”，只能是前者相似度更高。

# distance、similarity、score 是不同系统对“匹配程度”的不同数值表达，必须看具体系统定义。

# similarity threshold 相似度阈值（越大越相关），区分与distance threshold 距离阈值（越小越相关）
